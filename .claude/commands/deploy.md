# /deploy

Бот работает локально на этой машине (Windows, порт 8000, запуск через
`start.bat` / `python main.py`). "Деплой" здесь = commit + проверка + restart
процесса. Никакого внешнего сервера/Docker нет.

## Шаги

1. **Коммит изменений** — см. `/commit`. Если рабочая копия уже чистая,
   пропустить.

2. **Прогнать тесты:**
   ```bash
   cd /c/Users/Professional/Desktop/vk-post-reposting-bot/vk-post-reposting-bot
   python -m pytest tests/ -q --ignore=tests/test_playwright_ui.py
   ```
   Если есть упавшие тесты — **остановиться**, сообщить пользователю и не
   перезапускать бота со сломанным кодом.

3. **Проверить config.json валиден:**
   ```bash
   python -c "import json; json.load(open('config.json', encoding='utf-8')); print('OK')"
   ```

4. **Перезапустить процесс бота:**
   - Найти и остановить процесс на порту 8000:
     ```bash
     netstat -ano | findstr :8000 | findstr LISTENING
     # затем
     taskkill /PID <pid> /F
     ```
   - Запустить заново:
     ```bash
     start.bat
     ```
     (start.bat сам убивает процесс на 8000 перед запуском, так что таскилл
     можно пропустить и просто запустить `start.bat`)

5. **Проверить здоровье:**
   ```bash
   curl -s http://localhost:8000/health
   ```
   Ожидается `200 OK` / `{"status": "ok"}`.

6. Проверить последние строки `logs/bot.log` на ошибки при старте.

## Если что-то упало

- Тесты красные → не деплоить, исправить код, вернуться к шагу 2.
- Бот не отвечает на /health → посмотреть `logs/bot.log`, проверить что
  процесс реально запущен (`tasklist | findstr python`).
- Port 8000 занят чем-то посторонним → `netstat -ano | findstr :8000`,
  разобраться что это за процесс перед `taskkill`.

## Подтверждение перед перезапуском

Если бот сейчас активно публикует посты (видно в дашборде /
`is_publishing`/`is_autopilot` в логах) — спросить пользователя перед
перезапуском, чтобы не прервать публикацию на середине.
