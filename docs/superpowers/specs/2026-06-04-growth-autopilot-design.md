# Дизайн: Growth Autopilot для VK-пабликов

**Дата:** 2026-06-04  
**Статус:** Approved  
**Цель:** добавить отдельную страницу Growth Autopilot, не ломая текущий продовый поток скачивания и публикации.

---

## Цель

Growth Autopilot должен помогать быстро развивать VK-паблик за счет цикла:

```
источник контента -> выбор вирусных постов -> фильтры и антидубли ->
умное расписание -> публикация через текущий стабильный поток ->
сбор метрик -> обучение будущих решений
```

Система должна работать для любых ниш. Источником контента является только VK. Внешние сайты, Telegram, YouTube и серые парсеры не входят в дизайн.

Главное ограничение: текущий прод не ломаем. Новый режим добавляется отдельной страницей и отдельными сервисами. Существующие кнопки скачивания, публикации, мониторинга и текущий автопилот должны продолжить работать как раньше.

---

## Продуктовые правила

- Growth Autopilot работает с одним активным пабликом за раз.
- В проекте может быть несколько пабликов/профилей, но публикации планируются отдельно для каждого.
- Один и тот же пост не переносится между разными пабликами.
- Темп публикаций полностью регулируется в настройках. 24 поста в день является пресетом, а не жесткой константой.
- Если сильных постов не хватает, бот улучшает выбор фильтрами, шаблонами и алгоритмическим скорингом, а затем снижает фактическое число публикаций.
- Автопилот останавливается только по техническим стоп-причинам: токены, права, VK API, лимиты, пустая очередь, недоступность источника, ошибки записи.
- Плохая статистика не останавливает систему полностью. Она влияет на скоринг, рекомендации, расписание и будущий выбор постов.

---

## Режимы источников

### Один источник

Пользователь указывает одно VK-сообщество. Бот качает посты только из него и оптимизирует:

- какие посты брать;
- сколько постов публиковать в день;
- в какие часы и с какими случайными интервалами публиковать;
- какие типы постов лучше заходят в конкретном паблике.

Это базовый сценарий. Growth Autopilot не должен требовать пачку источников.

### Одобренные источники

Пользователь вручную добавляет несколько VK-источников. Бот ранжирует их по результатам и чаще берет посты из источников, которые дают лучший `growth_score`.

## Архитектура

Новые компоненты добавляются рядом с текущей системой:

| Компонент | Назначение |
|---|---|
| `Growth Engine` | Главный координатор режима роста для активного профиля |
| `Source Mode` | Выбор режима: один источник или одобренные источники |
| `Candidate Scoring` | Оценка постов по вирусному потенциалу |
| `Global Anti-Duplicate` | Общая память использованных постов по всем профилям |
| `Smart Scheduler` | План публикаций со случайными интервалами и лимитами |
| `Growth Tracker` | Сбор метрик через 1ч, 3ч и 24ч |
| `Learning Layer` | Обновление рейтингов источников, форматов и времени |
| `Algorithmic Rules` | Настройки, шаблоны и скоринг без внешних моделей |

Старый `publish_worker` остается основным стабильным механизмом публикации. Growth Autopilot должен сначала научиться готовить кандидатов и план, а затем передавать уже выбранные посты в существующий поток.

---

## Рабочий поток

1. Пользователь открывает отдельную страницу Growth Autopilot.
2. Выбирает активный профиль.
3. Выбирает режим источника: один источник или одобренные источники.
4. Нажимает `Раскачать паблик`.
5. Бот выполняет техническую проверку:
   - user token;
   - group token;
   - Group ID;
   - права на публикацию;
   - доступность VK API;
   - лимит отложенных постов;
   - доступность источников;
   - возможность записи в storage.
6. Бот собирает посты-кандидаты из выбранного режима источников.
7. Считает `viral_score`.
8. Отбрасывает глобальные дубли между всеми профилями.
9. Отбрасывает явный мусор, рекламу и запрещенные слова.
10. При необходимости и только если включено пользователем применяет шаблоны и правила обработки текста.
11. Строит план публикаций по настройкам темпа.
12. В dry-run показывает план без изменения очереди.
13. В queue/live режимах передает выбранные посты в существующий стабильный поток публикации.
14. После публикации Growth Tracker собирает метрики через 1ч, 3ч и 24ч.
15. Learning Layer обновляет рейтинги источников, времени и типов постов.

---

## Скоринг кандидатов

`viral_score` должен оценивать потенциальную силу поста до публикации.

Базовые факторы:

- лайки;
- репосты;
- комментарии;
- просмотры;
- свежесть;
- отношение реакций к просмотрам;
- сила источника по прошлой статистике;
- наличие фото/галереи;
- длина текста;
- отсутствие явной рекламы и мусора.

Скоринг должен быть объяснимым: UI показывает не только число, но и краткие причины, например `много репостов`, `сильный источник`, `свежий пост`, `хороший ER`.

---

## Антидубли

Нужна глобальная память использованных постов по всем профилям. Она должна предотвращать публикацию одного и того же материала в разные паблики.

Минимальный набор ключей:

- `source_owner_id`;
- `source_post_id`;
- дата первого использования;
- профиль, где использован пост;
- целевой VK post id после публикации, если известен;
- fingerprint текста;
- fingerprint набора фото, если доступен.

Если пост уже использован в другом профиле, Growth Autopilot пропускает его и выбирает следующий кандидат.

---

## Расписание и темп

В настройках нужен полный контроль:

- мин/макс постов в день;
- случайные интервалы;
- разрешенные часы публикации;
- ночной режим;
- запас очереди на N дней;
- лимит отложенных постов;
- минимальный `viral_score`;
- стратегия при нехватке сильных постов.

Простой режим показывает пресеты:

- осторожно;
- активно;
- агрессивно;
- свой.

Пресет `24 поста/день` должен быть одним из вариантов, но не константой в коде.

## Метрики и обучение

После публикации бот собирает метрики:

- через 1 час;
- через 3 часа;
- через 24 часа.

Метрики:

- просмотры;
- лайки;
- репосты;
- комментарии;
- общий `growth_score`.

`growth_score` используется для обучения:

- рейтинг источника;
- лучшие часы публикации;
- лучший диапазон постов в день;
- типы постов, которые заходят лучше;
- темы и длины текста;
- посты и источники, которые стоит реже использовать.

---

## Этапы внедрения

### 1. Read-only

Новая страница и API только анализируют текущие источники, очередь и кандидатов. Ничего не публикуется и не меняется.

### 2. Dry-run

Бот строит полный план публикаций и показывает, что бы сделал, но не трогает очередь и VK.

### 3. Queue

Бот добавляет выбранные посты в локальную очередь. Публикация идет через существующий стабильный `publish_worker`.

### 4. Live

Автопилот сам скачивает, выбирает и ставит посты в отложку через существующий поток. Технические стопы всегда включены.

---

## Что не входит в первую версию

- автоматический поиск источников по ключевым словам ниши;
- внешние источники за пределами VK;
- внешняя генерация текста;
- замена существующего publish/download потока;
- автоматическая остановка из-за плохой статистики роста;
- массовая одновременная публикация во все профили.

---

## Критерии готовности

- Есть отдельная страница Growth Autopilot.
- Старые сценарии скачивания и публикации работают как раньше.
- Можно запустить read-only/dry-run без изменения очереди.
- Можно выбрать один VK-источник и получить план публикаций.
- Можно использовать одобренные источники.
- Есть глобальный антидубль между профилями.
- Темп публикаций настраивается, 24/день не захардкожено.
- Метрики публикаций сохраняются и влияют на будущий скоринг.
- Внешние модели и генерация не используются.
